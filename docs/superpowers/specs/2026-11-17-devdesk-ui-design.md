# DevDesk 浅色管理界面设计

## 目的与状态

本设计记录 2026-11-17 对 task1 界面的讨论结论，并作为 task1 浅色界面改造的验收依据。task1 已实现服务实例登记与列表读取；扫描、状态查询、启停和详情仍是后续任务，界面不能提前显示虚假的可用功能。

## 视觉方向

- 固定浅色主题。以白色内容区、极浅灰导航区、浅灰分隔线和深灰正文为主；不跟随系统切换为深色。
- 配色克制。按钮以中性灰为主，不使用现有的深蓝黑背景、鲜蓝主按钮或多色装饰。运行、异常等语义颜色只用于少量状态标记，并配上文字，不能只靠颜色区分。
- 页面像日常使用的 Windows 管理工具：结构直接、信息清楚。避免巨大的标题、装饰性小标题、阶段徽标、过多圆角卡片、夸张阴影、插画和宣传式文案。
- 参考已选中的“表格总览”草图：顶部工具栏、紧凑表格、清晰的横向分隔。草图中的示例状态和未来页面只是布局示意，不代表 task1 已实现这些能力。
- 字体使用适合 Windows 中文界面的系统字体；正文保持易读，不靠过小字体或极密行距增加信息量。标题和按钮的层级清楚，但不做大型首页视觉区。

## task1 现阶段页面

- 顶部仅显示 `DevDesk` 和“添加服务”操作。重新扫描、运行环境、操作记录等未实现入口不显示。
- 当前只有一个可用页面，暂时隐藏左侧导航。后续有至少两个可用页面时，再采用所选草图的简短左侧导航，并只列出已实现页面。
- 主区域显示“服务实例”标题、按实例名称或 Windows 服务名查找的简单搜索框，以及已登记服务表格。当前表格仅列“实例名称”“Windows 服务名”“预期端口”。没有状态查询前，不显示服务状态、端口状态、启停或详情入口。
- 没有实例时，仅显示一句简短说明与“添加服务”按钮。不使用插画、大卡片或重复的引导文案。搜索无结果时明确写“未找到匹配的服务”，不误写成“尚未登记服务”。
- 点击“添加服务”打开简洁弹窗，包含当前已有的实例名称、Windows 服务名、预期端口三个字段；沿用现有校验规则。保存成功后关闭弹窗并刷新表格，失败时保留输入并显示错误。弹窗支持明确的取消和关闭操作。
- 本次 UI 改造以 `src/App.vue` 和 `src/components/InstanceForm.vue` 为主要界面范围，保留 task1 已实现的 Rust 存储与前端调用契约。具体组件拆分由实施者根据可读性决定，不为样式改造增加无关业务层。

## 后续功能进入时的界面演进

- 自动发现完成后，已登记实例仍用主表格，待确认对象在表格下方单列；未核对登记的候选只读。
- 状态查询完成后，表格把“服务状态”和“端口状态”分为两列。服务运行但端口未监听时，分别显示真实结果，不合成误导性的“正常”状态。
- 启停完成后，每行提供随状态变化的常用“启动”或“停止”以及“详情”；常规停止先显示服务名并确认一次。强制结束等高风险操作只放在独立详情页，使用更严格的确认。
- 详情使用独立页面，容纳配置、日志与操作历史。只有对应功能完成后才加入导航或操作入口。
- 服务数量增加时仍保持中等信息密度，优先提供名称搜索，不在第一版加入复杂筛选。

## 验收要点

- 启动与空列表状态均为浅色，不能因 Windows 深色主题变为深色页面。
- 当前 task1 只显示真实可用的登记、搜索和列表能力；无未实现功能的占位按钮。
- 添加弹窗在保存成功、保存失败、取消和字段校验时行为清楚；保存后的数据仍能在重开应用后读取。
- 列表在实例名称较长、Windows 服务名较长、端口未设置和搜索无结果时保持易读。
- 视觉上没有旧版深蓝黑底、鲜蓝按钮、大卡片、装饰性阶段标签或巨型标题。

## 参考实现与约束

浅色样式与列表、弹窗逻辑集中在 `src/App.vue`，登记表单与字段校验在 `src/components/InstanceForm.vue`。后续扩展页面时保留现有保存与校验行为，并按已实现的功能逐步加入入口。
