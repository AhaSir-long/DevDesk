# DevDesk 第一版设计稿

## 目标与使用场景

DevDesk 是供个人使用的 Windows 本机服务与运行环境管理工具。用户打开它后，应能看见已安装和正在运行的开发相关对象，确认具体服务实例，查看状态、端口、路径与日志，并安全地启停服务或修改其监听端口。

第一版以当前机器上的 MySQL80 和 Redis Windows 服务作为真实验收样本。两者目前分别监听 3306 和 6379；MySQL 服务指向 `C:\ProgramData\MySQL\MySQL Server 8.0\my.ini`，Redis 服务指向安装目录中的 `redis.conf`。这些是检查时的机器事实，不是写死在程序里的默认路径。当前检查未发现 Nacos。

## 第一版范围

- 自动发现 Windows 服务中已安装或正在运行的 MySQL、Redis 实例；从环境变量、PATH、当前进程和用户指定的目录补充发现。目录扫描限制深度，界面显示扫描范围，允许直接指定安装目录。不进行全盘扫描。解压版可作为候选被发现，但第一版不自动推断其完整启停和配置修改方式。
- 展示 JDK、Node.js、Maven、Git 等运行环境的版本、安装路径及 PATH 实际解析位置。运行环境只读，不作为可启停的服务。
- Nacos、Java/Node.js 业务程序以及解压版 MySQL/Redis 允许手动登记启动命令、工作目录、预期端口、可选停止命令与日志文件；支持 `.cmd`、`.bat` 脚本。自动识别这些程序的专用规则后续逐步增加。
- 按具体服务实例显示状态。自动发现结果在用户核对并登记前是候选对象，只能查看；不按软件类型或进程名批量启停。
- 对已登记实例启停和修改监听端口。Windows 服务按需 UAC 提权，主程序始终以普通权限运行。外部启动且身份或控制方式不可靠的进程只监看。
- 浏览已识别的管理字段和对应文件位置，使用系统编辑器打开完整配置文件。第一版的表单修改仅支持已明确识别的端口字段，不提供通用配置编辑器。
- 查看操作结果、失败原因、可识别的日志文件和由 DevDesk 启动程序的标准输出。DevDesk 退出后，仍在运行的程序继续将新输出写入日志，重新打开可接着查看。保存简洁的本地操作历史，不记录密码或完整环境变量。
- 本机 SQLite 保存登记信息、扫描目录和操作历史；配置备份保存为独立文件。第一版先交付本机可运行版本，换机迁移与便携模式按实际需要后置。

## 主要界面

已确认的浅色界面细则及 task1 过渡状态见 [DevDesk 浅色管理界面设计](./2026-11-17-devdesk-ui-design.md)。其中 task1 只展示已实现的登记、搜索和列表能力。

首页先展示已登记服务及明确识别的候选，包含名称、实例标识、Windows 服务状态、端口状态、路径和最近操作结果。不确定的进程单列在待确认区域，避免把所有 `java.exe`、`node.exe` 当成业务服务。已登记实例定时刷新运行状态；发现新安装或 PATH 变化由手动重新扫描触发。

界面固定使用浅色、克制的视觉风格，不使用深色主题或花哨配色。首页以紧凑列表呈现服务实例，避免大面积卡片。顶部只保留简短标题和必要操作，不显示“本机服务工作台”“第一阶段”等装饰性文案或徽标。登记入口是“添加服务”按钮，表单按需打开，不常驻首页右侧。整体取向是直接、务实的 Windows 管理工具，同时保持清晰易读。

首页采用“表格总览”布局：左侧为简短导航，右侧以表格列出已登记的服务实例，待确认对象在表格下方单列。用户已从两版浅色草图中选择这一布局；另一版将服务与运行环境混排在同一长页，不作为第一版首页方向。

服务表格将“服务状态”和“端口状态”分列，避免把进程存在误显示为端口可用。每行提供随当前状态变化的常用操作（启动或停止）及“详情”，强制结束等高风险操作只在详情中出现。详情使用独立页面以容纳配置、日志和操作历史；左侧导航只显示已经可用的页面，后续功能完成后再加入相应入口。

“添加服务”使用简洁弹窗，第一阶段登记字段为实例名称、Windows 服务名和预期端口，保存成功后关闭并刷新列表。尚无实例时仅显示简短说明与添加按钮，不使用插画或大面积空状态卡片。已登记实例的常规停止先显示服务名并确认一次；强制结束使用独立的更严格确认。表格上方提供按实例名称或 Windows 服务名查找的简单搜索，不在第一版加入复杂筛选。

详情页展示实例身份、服务状态与端口监听状态、配置文件、已识别字段、日志和操作历史。服务显示“正在运行但预期端口未监听”等组合状态，不将进程存活等同于可用。界面上的耗时扫描、日志读取和端口查询均在后台运行，不阻塞交互。

## 核心操作

### 登记与启停

候选服务需展示发现来源、Windows 服务名或程序路径、配置文件和预期端口，用户核对后登记。同类软件的多个实例按服务名、配置文件及端口分别管理。启动和停止前重新读取对象身份与状态；重复点击不得创建重复进程或并发执行同一操作。

Windows 服务通过系统服务管理接口操作；需要权限时只对本次操作请求 UAC。用户取消或权限不足时显示明确结果。停止超时保留当前状态与错误信息，不自动强制结束；强制结束是单独的显式确认操作。

手动登记的程序由 DevDesk 按工作目录和启动命令启动，保存进程身份信息。启动脚本退出后可能留下实际服务进程，不能把脚本 PID 当成服务 PID。停止时先用用户配置的停止命令；没有停止命令时尝试对已确认的实际进程正常停止，失败后由用户单独确认是否强制结束。关闭 DevDesk 默认不停止这些程序；重新打开时核对实际进程身份，匹配后才恢复管理能力，无法核对时只监看并禁用停止。

### 修改端口

第一版为已登记的 MySQL、Redis Windows 服务提供已知配置格式的端口修改。解压版与其他手动登记程序不自动改写配置文件。操作前检查新端口是否被监听；占用时展示可读取的 PID、进程名、路径等证据，并阻止本次修改。DevDesk 不自动结束占用进程。进程信息无法读取时明确标记未知，不伪造身份。

确认页展示服务实例、配置文件、旧端口、新端口和连接中断提示。MySQL 的 `[mysqld]` 监听端口是必改项，`[client]` 默认连接端口由用户在本次操作中选择是否同步修改。只修改所选字段，其他配置保持原样；修改前备份原文件。运行中的服务先停止、修改、再启动；停止中的服务只修改配置，下一次启动时生效。操作后核对服务状态与新端口监听情况。

如修改或启动失败，保留错误现场、备份与操作记录，提供明确的恢复备份入口；恢复后再次核对服务和端口状态。恢复不自动覆盖其他人后来对配置文件作出的修改，存在变化时先提示用户核对。其他项目中写死的连接端口不由 DevDesk 自动修改。

## 实现方案

桌面外壳使用 Tauri 2，界面使用 Vue 3 与 TypeScript；Windows 服务、进程、端口、配置文件和本地存储由 Rust 侧实现，界面通过受限命令调用与事件接收结果。Rust 侧以服务实例为操作单位，分别实现 Windows 服务与手动命令程序的控制方式。MySQL、Redis 配置解析和端口修改各自实现明确规则，不以通用文本替换处理任意文件。

需要管理员权限的服务启停或受保护文件修改，采用短时运行的受限提权操作，结束后立即退出。提权入口只接受受支持的操作类型和经过核对的目标，不接受任意 shell 命令。具体调用与校验协议在实施前做安全设计和验证。

进程接管记录至少包含 PID、创建时间及可读取的可执行文件身份；停止前重新核对，无法可靠匹配时降级只读。DevDesk 启动程序时将标准输出和标准错误重定向到持久日志文件，使界面退出后输出仍可落盘；脚本及多级子进程场景需通过实际测试验证输出继承。日志读取、目录扫描和状态刷新采用后台任务，并限制刷新频率与界面缓存，避免高频输出拖慢界面。

技术路线的取舍见 `docs/adr/0002-桌面技术路线.md`。不预设 Tauri 与 WinUI 3 的性能差距；用首条真实流程实测启动、刷新与日志期间的界面响应。

## 验收场景

1. 启动应用后发现本机 MySQL80、Redis 及 JDK、Node.js、Maven、Git；停止的已安装服务仍能显示。扫描候选不被自动当作可操作实例。
2. 登记 MySQL80 和 Redis，重启 DevDesk 后信息仍在；多个同类实例互不混淆。
3. 分别启停 MySQL80、Redis；核对真实服务状态和监听端口。取消 UAC、权限不足、停止超时均有明确结果，其他服务不受影响。
4. 用占用进程模拟目标端口冲突：显示占用证据，取消后配置和服务状态不变。再选空闲端口，确认中断、备份、修改、重启并验证新端口。失败时可查看原因和恢复备份。
5. 登记并通过 `.cmd` 或 `.bat` 启动一个测试用 Java/Node.js 程序，关闭 DevDesk 后程序继续运行且新输出持续落盘；重新打开时核对实际服务进程身份后可管理，身份不匹配时只监看且不能停止。
6. 日志和操作记录在重开后可查看；高频日志与持续刷新时界面仍可操作，历史中不出现密码或完整环境变量。

验收优先使用隔离测试服务和测试程序。对本机实际 MySQL80、Redis 的写操作需由用户在实施或验收时明确决定，不能为验证设计稿擅自中断现有服务。

## 已确认的补充规则
